# SLI / SLO・アラート運用方針

> ステータス: 方針確定。実環境での計測・通知試験は本番環境確定後に実施する。

## 1. SLI 定義

| SLI | 定義 | 計測方法 |
|---|---|---|
| 可用性 | `/health` が 200 かつ JSON `status=ok` / `database=ok` を返した時間割合 | ヘルスチェックプローブ（例: 30秒間隔） |
| 応答時間 | API 主要エンドポイントの p95 応答時間 | アプリログのレイテンシ集計 |
| エラー率 | 5xx 応答 / 全応答 | アプリログ・リバースプロキシログ |
| バックアップ成功率 | 日次バックアップの成功数 / 実行数 | バックアップスクリプトの exit code |
| DB接続率 | DBプール使用率（80%超を異常とする） | PostgreSQL `pg_stat_activity` |
| 容量 | ディスク・MinIO・DB使用率 | `df` / MinIO health / PGサイズ |

## 2. SLO 目標（初期）

| 指標 | 目標 | 備考 |
|---|---|---|
| 月間可用性 | 99.5%（業務時間 8:00-18:00） | 単一ホスト構成のため緩やかな初期目標 |
| p95 応答時間 | 一覧・遷移 API 2秒以内、ログイン 3秒以内 | 本番相当負荷試験で再計測 |
| 5xx エラー率 | 1% 未満 | 監視基盤導入後は 0.5% 目標へ |
| バックアップ成功率 | 100%（失敗時は翌日までに手動リカバリ） | RPO 24h / RTO 8h |

## 3. アラート閾値・通知先・エスカレーション

| レベル | 条件 | 通知 | 一次対応 | エスカレーション |
|---|---|---|---|---|
| Warning | 5xx率 >0.5%、DB接続 >70%、ディスク >70%、バックアップ失敗 | IT担当メール/Teams | IT担当 | 翌営業日までに調査 |
| Critical | サービス停止、5xx率 >2%、ディスク >85%、DB接続 >85%、バックアップ連続2日失敗 | 即時通知（電話を含む） | IT担当 | 30分応答・1時間以内に復旧判断 |
| Security | 認証失敗急増、監査ログ改ざん試行、ウイルス検知 | 即時通知 | セキュリティ担当 | インシデント対応手順へ移行 |

通知基盤（メール/Teams/Slack）は本番環境確定時に設定し、**通知試験はその時点で実施**する。

## 4. 監視対象と確認方法（本番環境確定後）

- 死活: `GET /health`（HTTP 200だけでなく JSON `status=ok` / `database=ok` を検証。DB必須・Redis参考）
- リソース: `docker stats` / `df -h`（スクリプト化推奨）
- ログ: `docker compose logs` / journald（構造化ログは structlog）
- バックアップ: `scripts/backup.sh` の exit code と出力
- 証明書期限: `openssl x509 -enddate` 定期確認（月次）
