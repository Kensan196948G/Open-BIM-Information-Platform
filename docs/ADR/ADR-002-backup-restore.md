# ADR-002: バックアップ自動化と復元演習

- ステータス: **Accepted（実装済み・運用開始後に復元実績を蓄積）**
- 決定日: 2026-08-05
- 対象: 可用性・災害対策

## 背景

評価レポートの重大指摘の一つ。PostgreSQL・MinIO・設定ファイルのうち一つでも失われると
正本化した図面・証跡を失う。手順書のみで自動化・暗号化・復元試験がなかった。

## 判断

1. **バックアップは `scripts/backup.sh` で日次自動実行**（systemd timer / cron 前提）。
   - PostgreSQL: `pg_dump` 論理バックアップ → gzip → 暗号化（OpenSSL AES-256-CBC）
   - MinIO: `mc mirror` を利用（コンテナ内で実行）→ 暗号化
   - 設定（`.env`・Compose・systemd unit）も同一バンドルに含める
   - 世代管理: 日次7世代・週次4世代・月次12世代を保持
   - 失敗時は終了コード＋ログで検知（監視基盤が入るまでは管理者メール/通知を別途設定）
2. **バックアップはアプリとは別の障害ドメインへ保存**（NAS/別拠点/オブジェクトストレージ）。
3. **復元演習は `scripts/restore-drill.sh` で隔離環境に復元**し、以下を記録する:
   - RPO/RTO 実測
   - レコード件数（projects/containers/audit_logs）
   - サンプルファイルのSHA-256一致
   - 監査ログの immutable トリガー再適用確認
4. **目標値（初期）**: RPO 24時間 / RTO 8時間。HA/DR構成（Phase 3）で引き締める。

## 結果

- 運用者はバックアップの存在を手動で覚える必要がなく、復元は手順書＋スクリプトで再現できる。
- 暗号鍵の管理（`BACKUP_ENCRYPTION_KEY`）が新たな運用責務となる（鍵管理基盤導入まで環境変数で管理）。
